# SpendSeal 控制台（团队预算池）

`index.html` — 单文件、**无 CDN、无后端**（链上读写为手写最小 ABI 编解码）。配置写死：
池子合约地址、USDC、链 ID 与演示地址簿，舞台上不手输地址。

一个池子 · 多张卡 · 分账可查 · 超额要人批。

## 功能

- **只读区**（打开即有数据，无需连钱包）：
  - 预算池：余额（所有卡共享）、今日全池已花 / 总日限进度条、单笔上限、累计总支出；
  - 分账：每张卡一张卡面，显示自己的今日已花 / 子额度，涨满变红；
  - 池子动态：链上事件流（付款、被拒、申请、批准/拒绝），按区块号标注；
  - 待批申请：Agent 发起的超额申请，主人在这里批准或拒绝。
- **写操作**（需连接主人钱包，MetaMask 等）：
  - 批准 / 拒绝待批申请 —— 批准即付款，只有主人能批；
  - **熔断整个池子**（红色大按钮 + 二次确认，明示不可恢复，余额仍可提回）。
- 每 4 秒自动刷新。

## 钱包写入的安全约束

页面会真正动用 USDC，所以写路径按「失败即不发」实现：

- 切链失败不吞：`wallet_switchEthereumChain` 失败会显式报错，而不是静默继续；
- 每次写交易前重新读 `eth_chainId` 校验，并在 `eth_sendTransaction` 里显式带上 `chainId`；
  校验不过一律不发送；
- 待批申请的**金额、收款方、Agent、状态一律回链上 `getRequest` 读**，链上日志只用来发现
  requestId，避免陈旧日志让主人批准一个链上不会执行的数值；
- 批准前用链上当前 `singleLimit` 复核申请金额，超出则拒绝签名。

> **已知合约层缺口（如实记录）：** 当前部署的 `PoolVault.approveRequest` 不复核
> `singleLimit`——审批在设计上只覆盖两个日限，但旧上限下开的申请在主人批准时会按记录金额
> 放行。上面的控制台复核只是 preflight，**不是原子性保证**。只有 owner 能调 `approveRequest`，
> 所以这不是外部攻击面，而是主人自己的护栏问题。下一次部署应在合约里补
> `if (r.amount > p.singleLimit) revert OverSingleLimit();`。

## 本地打开

```bash
cd web && python3 -m http.server 8080
# 浏览器开 http://localhost:8080/
# 批准/熔断时连主人钱包，网络切到 Monad Testnet 10143
```

## 已知约束

- **Monad 公共 RPC 限制 `eth_getLogs` 单次最多 100 个区块**（实测错误 -32614）。页面分块扫描，
  默认只看最近约 3,000 个区块，之后用水位线增量扫描。
- 因为扫描窗口有限，**早于窗口的历史事件不会出现在「池子动态」里**（链上状态本身不受影响：
  余额、日累计、分账都是直接 `eth_call` 读的，永远准确）。若演示需要看到更早的历史，应换带索引
  的 RPC/浏览器 API，而不是加大窗口硬扫。
- 首次加载要串行打约 30 次 `eth_getLogs`，在公共 RPC 上可能耗时 10 秒以上，期间顶栏显示
  「连接中…」。**正演时提前打开页面预热，不要临场刷新。**

## 验证

人工核对：打开页面，确认池余额、今日已花 / 总日限、每张卡的分账与链上一致
（`docs/deployments.md` 记录了部署时的读数），且「池子动态」在付款后 4 秒内出现新事件。
