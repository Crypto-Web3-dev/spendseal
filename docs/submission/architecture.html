🦭 SpendSeal — Architecture

A sealed spending allowance for your AI agent · Monad Testnet (chain 10143) · PassportVault 0x8881…7cf1
AGENT SIDE · DESKTOP

🤖 Claude Desktop + spendseal-mcp

Only two MCP tools: pay_for_api and read-only passport_status. No management tools exist — by design.

IDENTITY · DISPLAY ONLY

🪪 ERC-8004 Registry

Agent identity agentId 2560. Discovery only — never consulted by the payment path.

SELLER · LOCAL SERVICE

📸 Paid Screenshot API

HTTP 402 + EIP-712 signed invoice (signer = payee). Verifies the vault's PaymentExecuted event, consumes each invoice exactly once, then delivers the PNG.

OWNER

👤 Owner Console

MetaMask-signed only: deposit, limits, whitelist, rejection logging, kill switch. Revoking never locks the owner's funds.

ON-CHAIN · MONAD

🏦 PassportVault

Holds USDC per passport. Every payment checked in-contract, in fixed order: exists → not revoked → not expired → whitelisted → per-payment cap → daily cap (UTC) → balance. Optional on-chain rejection audit.

① GET → 402 + signed invoice
⑤ retry + tx hash → ⑥ verified → PNG
② verify signature → ③ checkPay → tryPay
④ USDC to seller (only if every rule passes)
owner txs only
Funds isolation — the agent address holds only gas; USDC can move solely through the vault's checks.
Two doors — signatures prove the quote is authentic; the passport enforces the rules. Neither replaces the other.
Bounded blast radius — a leaked agent key loses at most one day's allowance (demo: 0.20 USDC).
